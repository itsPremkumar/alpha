docs: triage the AGI roadmap against measured reality

The roadmap proposes a 56-package tree and ~30 phases. Measured against the
repository, 12 of its 13 named packages already exist totalling ~140,000 lines,
and several of its "missing" P0 capabilities are already built and running.

This document maps every phase group to `EXISTS / PARTIAL / MISSING /
CONTRADICTS`, so the roadmap becomes an accurate work plan instead of a
rewriting program.

## Why this file lives at the repository root

`docs/INDEX.md` is generated by `scripts/generate_docs_index.py`, which fails
closed on unclassified Markdown under `docs/`. This is a working planning
artifact, not part of the published documentation set.

## The headline finding

`§78` proposes this tree:

```
alpha/
├── cognitive/     ├── reasoning/   ├── coding/      ├── evolution/
├── runtime/       ├── orchestration/ ├── research/  ├── observability/
├── goals/         ├── tools/       ├── evaluation/ └── security/
└── memory/
```

Measured today:

| Package | Files | Lines |
| --- | ---: | ---: |
| `memory/` | 148 | 42,952 |
| `tools/` | 150 | 24,064 |
| `runtime/` | 106 | 30,555 |
| `security/` | 28 | 3,897 |
| `evolution/` | 23 | 8,166 |
| `observability/` | 23 | 11,348 |
| `reasoning/` | 16 | 4,760 |
| `orchestration/` | 13 | 2,533 |
| `coding/` | 10 | 3,743 |
| `research/` | 5 | 1,767 |
| `evaluation/` | 4 | 1,695 |
| `goals/` | 3 | 296 |
| `cognitive/` | — | **missing** |

`§93` of the roadmap states: *"Do not create duplicate parallel implementations if
an existing Alpha package already owns the behavior."* `§78`'s tree, built
literally, violates that on 12 counts. It would also break
`contracts/feature_manifest.json` (112 generated engines), trip
`test_no_orphan_modules.py`, and fork every subsystem that
`backend/AGENTS.md` currently assigns a single owner to.

**Read §78 as a naming wishlist, not a migration plan.**

## Phase triage

### Phase 0 — freeze the baseline (`§7`) — PARTIAL, and already running

`generate_feature_manifest.py` produces exactly the JSON `§7` asks for, and
`tests/test_feature_manifest_wiring.py` pins every registry entry to a module
that imports it. `test_no_orphan_modules.py` is the orphan detector. What is
missing is a *documented baseline snapshot*; the generator is the mechanism.

Note: regenerating it during earlier remediation work **fixed a genuinely failing
CI gate** — the committed manifest had drifted from the routers actually mounted.

### Phase 1 — reliability substrate (`§8`) — MOSTLY EXISTS

| §8 item | Reality |
| --- | --- |
| 8.1 run state machine | **EXISTS** — `runtime/sessions/states.py`, 17 lifecycle states plus `ACTIVE`/`WAITING`/`TERMINAL` classification, with precedence rules |
| 8.2 durable execution | **EXISTS** — LangGraph checkpoints, `CheckpointStateAccessor`, delta/full channel modes, `RunJournal` |
| 8.3 side-effect ledger | **EXISTS and in production** — `deps.py` wires `SqlSideEffectLedger` + `SideEffectReclaimer` into the process-wide recorder |
| 8.4 worker leasing | **EXISTS** — `RunRecord.lease_expires_at`, bounded renewal, ownership-loss fence |
| 8.5 fleet-wide ESTOP | **WAS MISSING** — see below |
| 8.6 recovery | **EXISTS** — `SafeRunRecoveryService`, fail-closed around pending tool nodes |

The honest caveat, already documented in
`packages/harness/alpha/runtime/AGENTS.md`: with `database.backend: memory` there
is no durable side-effect store, and the JSON/JSONL state behind swarms and
dynamic workflows is process-local and restart-recoverable, **not** cross-process
exactly-once.

### ESTOP (`§3.2`, `§8.5`, P0) — WAS NOT FLEET-WIDE. Now fixed.

Verified before this work: `alpha.runtime.estop`'s **only** consumer was
`alpha.rsi.switchboard`. `runtime/runs/worker.py` did not reference it; the
autonomy supervisor did not either. An operator engaging the emergency stop was
told *"Fleet execution paused."* while the fleet ran on.

Shipped in `bac2f0d` (see below): `runtime/control.py` with a **monotonic
generation fence**, wired into run admission and the autonomy tick.

### Phase 2 — mission/goal system (`§9`) — PARTIAL

`projects/goals.py` (durable goal tree with attempts and progress) and
`agents/goal_state.py` exist. **But `goals/` is 296 lines across 3 files, and the
`runtime/` plane has no importer of it.** The run loop's goal is a flat objective
string. This is a genuine gap and a good next unit of work.

### Phase 4 — memory fabric (`§11`) — EXISTS, with named limits

148 files / 42,952 lines, with `memory/cognitive/AGENTS.md` as the normative
contract. `§11`'s "12 memory types" is a superset; the layering, provenance and
owner-scoping exist. Open item from the audit: memory injected into the lead
prompt is not escaped against injection (`F-54`).

### Phase 5–6 — self/world model, one cognitive kernel — MISSING

`cognitive/` is the one genuinely absent package. `§6`'s kernel interface is a
reasonable shape, but it should be introduced as **composition over existing
engines**, not as a new loop: `§93` explicitly warns against *"another generic
agent loop"*.

### Phase 12 — behavioural evaluation (`§19`, P0) — THE BIGGEST REAL GAP

1,270 test files. **Zero** evaluate whether the agent behaves correctly — whether
it chose a sane plan, used appropriate tools, stopped when it should, recovered
from failure, retained relevant memory, or completed the actual task.
`benchmarks/suites.py` evaluators are pure functions over fixtures.

This is the highest-value missing capability, and it is also what makes every
later phase falsifiable. Without it, "self-improvement" has no measurement.

### Phase 13–15 — RSI, evolution, harness safety — EXISTS, and is stricter than the roadmap assumes

`rsi/` is 22 files with `promotion.py`, `holdout.py`, `evidence_bundle.py`,
`lineage.py`, `archive.py`, `review.py`, `shadow.py`. Critically,
`holdout.holdout_gate` **only passes on `evidence_kind="measured"`** — the
roadmap's `§30` evaluator-first principle is already enforced in code.

What `run_rsi_cycle` lacked was honesty about not measuring, which is fixed
separately: it previously hardcoded `0.72 → 0.88` so `improved` was always true.

`§22`'s "immutable safety kernel" is the one structural idea worth adding, and
it is cheap: mark the safety-policy, approval, ESTOP, promotion-gate and audit
modules as non-self-modifiable.

### Phase 10 / §17.3 — frontier coding agent — PARTIAL, and the largest gap

`sandbox/worktrees.py` is 338 lines of correct, hardened code with **no tool,
route, or caller**. Nothing commits, reviews, or merges. This is the single
largest honest gap in the product and the roadmap correctly identifies it.

### Phase 39–40 — observability and replay — PARTIAL

`observability/` is 23 files / 11,348 lines. `X-Trace-Id` correlation, the
run-event feed and `RunJournal` work. Two real gaps: the trajectory flight
recorder's writer is never installed in production, and there is no
`observability:`/`trace:` key in `AppConfig`, so span tracing is not reachable
from `config.yaml` at all.

## Revised priority order

The roadmap's `§76` order is sound in shape. Adjusted for what is actually
missing:

| # | Work | Why now |
| --- | --- | --- |
| 1 | **Behavioural evaluation plane** | Nothing else can be proven; blocks every claim below |
| 2 | **Wire `goals/` into the runtime** | Real gap, small, removes the flat-objective limitation |
| 3 | **Trace writer + `config.yaml` reachability** | Cheap; makes existing 11k lines observable |
| 4 | **Typed git tool + worktree orchestration** | Largest capability gap; existing library does the hard part |
| 5 | **Immutable safety kernel** | Cheap; makes RSI structurally safe |
| 6 | **`cognitive/` kernel** | Genuinely new, and only worth building once (1) can measure it |

Deferred as already-satisfied: `§8.1`–`§8.4`, `§8.6`, `§13` promotion gates.

## What this document is not

It is not a rejection of the roadmap. Most of its *content* is correct and its
"do not duplicate" warning is exactly right — the tree in `§78` is the one place
it contradicts itself. Read it as a specification of intent, then implement
against the packages that already own each behaviour.
