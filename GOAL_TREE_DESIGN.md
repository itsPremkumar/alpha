# Goal Tree Design Plan\n\n## The Gap\n\nAlpha has **four disconnected goal systems**, none of which provides a hierarchical goal tree wired into the run loop:\n\n| System | Location | What it has | What it lacks |\n|---|---|---|---|\n| **Run-loop GoalState** | `mission/goalloop/state.py` | `objective: str`, `subgoals: list[str]`, turn budget, gates, judge | Sub-goals are flat strings — no IDs, no state, no parent-child, no evidence, no independent lifecycle |\n| **Versioned Plan Store** | `goals/` (GoalContract / PlanVersion / TaskAttempt) | Owner-scoped, approval state machine, atomic writes, attempt tracking | No parent-child between contracts, no execution states, **no run-loop caller**, no decomposition |\n| **APEX Goal Store** | `apex/goals.py` (ApexGoal) | `parent_goal_id`, `child_ids`, `success_criteria`, `evidence`, 15-state enum, `create_child`, `tree()`, evidence-gated completion | Not wired into the run loop; not connected to planning; separate persistence |\n| **Continuous Goal Runner** | `harness/continuous/` | Milestones with dependencies, iteration budget, self-healing | Milestones are flat within a goal; no tree; no connection to `alpha.goals` or `apex.goals` |\n\nThe planning module (`planning/`) compiles a goal string into an `ExecutionPlanIR` with a `task_dag` and `execution_waves`, but the resulting plan is **not linked to any goal store** — it's a one-shot compile-and-dispatch.\n\n**The core problem:** The run loop treats the goal as a flat objective string. There is no hierarchical decomposition, no independent sub-goal lifecycle, no evidence tracking per sub-goal, and no connection between "what to do" (plans) and "why it matters" (goal tree).\n\n---\n\n## Design: A Unified Goal Tree\n\n### Core Idea\n\nIntroduce a **`GoalNode`** tree that is the single source of truth for "what we're trying to achieve and why." Each node has its own objective, success criteria, evidence, and state. The run loop walks the tree. The planning module compiles plans *for specific nodes*. The versioned plan store records the contract/plan/attempt history *for those nodes*.\n\n### Architecture\n\n```\n┌─────────────────────────────────────────────────────────┐\n│                    Run Loop (engine)                     │\n│  ┌─────────────┐  ┌──────────────┐  ┌───────────────┐  │\n│  │ GoalTree    │→ │ TreeWalker   │→ │ NodeExecutor  │  │\n│  │ (in-memory) │  │ (selects     │  │ (runs one     │  │\n│  │             │  │  next node)  │  │  node's plan) │  │\n│  └─────────────┘  └──────────────┘  └───────────────┘  │\n│         ↑                                    ↓          │\n│         │                           ┌───────────────┐  │\n│         └───────────────────────────│ Evidence      │  │\n│                                     │ Recorder      │  │\n│                                     └───────────────┘  │\n└─────────────────────────────────────────────────────────┘\n         ↑                                    ↓\n┌─────────────────────┐          ┌─────────────────────────┐\n│  Goal Tree Store    │          │  Planning Module        │\n│  (durable, per-     │          │  (CognitiveCompiler     │\n│   session)          │          │   → ExecutionPlanIR)    │\n│                     │          │                         │\n│  GoalNode records   │          │  Compiled for a         │\n│  with parent_id,    │          │  specific GoalNode,     │\n│  criteria, evidence │          │  linked back via        │\n│  state, plan links  │          │  node.plan_version      │\n└─────────────────────┘ decomposition, │\n│  TaskAttempt per    │\n│  execution wave     │\n└─────────────────────┘\n```\n\n---\n\n## Data Model\n\n### GoalNode (new — replaces `subgoals: list[str]` in GoalState)\n\n```python\n@dataclass\nclass GoalNode:\n    node_id: str                          # "gn-<hex>"\n    parent_id: str                        # "" for root\n    objective: str                        # what this node is trying to achieve\n    success_criteria: list[str]           # what "done" means for this node\n    constraints: list[str]                # guardrails inherited from parent\n    priority: int                         # 0-100, inherited ceiling from ancestors\n    state: NodeState                      # see below\n    evidence: list[GoalEvidence]          # append-only measurements\n    plan_version: int                     # which plan version this node is executing\n    plan_id: str                          # link to versioned plan store\n    child_ids: list[str]                   # ordered\n    session_id: str\n    created_at: float\n    updated_at: float\n    # --- derived ---\n    @property\n    def is_terminal(self) -> bool: ...\n    @property\n    def is_active(self) -> bool: ...\n    @property\n    def criteria_without_evidence(self) -> list[str]: ...\n    @property\n    def criteria_failed(self) -> list[str]: ...\n```\n\n### NodeState (new — 12 states, simpler than APEX's 15)\n\n```\nIDLE → ANALYZING → DECOMPOSING → EXECUTING → VERIFYING → COMPLETED\n                                    ↓              ↓\n                               REPLANNING      RECOVERING\n                                    ↓              ↓\n                                  BLOCKED ←────────┘\n                                    ↓\n                               FAILED / CANCELLED\n```\n\nKey differences from existing systems:\n- **DECOMPOSING** is a first-class state — the node is actively breaking itself into children\n- **REPLANNING** increments `plan_version` and links to a new `PlanVersion`\n- **COMPLETED** requires all `success_criteria` to have passing evidence (same gate as APEX)\n- **PARTIAL** is reachable from VERIFYING when some criteria hold but others don't\n\n### GoalEvidence (reuse from `apex/goals.py`)\n\nAlready well-designed: `evidence_id`, `criterion`, `source`, `detail`, `holds: bool | None`, `recorded_at`. The `latest_evidence()` pattern (most recent measurement per criterion) is the right model.\n\n### Changes to GoalState (mission/goalloop/state.py)\n\nReplace `subgoals: list[str]` with `nodes: dict[str, GoalNode]` (or a separate `GoalTreeStore` that the run loop consults). Keep `objective` as the root node's objective. The `GoalState` becomes the root of the tree.\n\n---\n\n## Wiring Into the Run Loop\n\n### Current Flow (flat)\n\n```\nGoalLoopEngine.run():\n  while not done:\n    gates = run_gates(goal)\n    verdict = judge(goal, evidence)\n    if verdict == "done": break\n    continuation = build_continuation_prompt(goal, evidence)\n    agent_turn(continuation)\n    consume_turn()\n```\n\n### New Flow (tree-walking)\n\n```\nGoalLoopEngine.run():\n  while not done:\n    node = tree.next_runnable_node()        # ← NEW: tree walk\n    if node is None:\n      # All nodes terminal — check if root is COMPLETED\n      break\n\n    if node.state == DECOMPOSING:\n      children = decompose(node)            # ← NEW: LLM breaks node into children\n      node.state = EXECUTING\n      continue\n\n    if node.state == EXECUTING:\n      plan = get_or_compile_plan(node)      # ← NEW: plan per node\n      result = execute_plan(node, plan)     # ← NEW: dispatch to bridge\n      record_evidence(node, result)\n      node.state = VERIFYING\n      continue\n\n    if node.state == VERIFYING:\n      if all_criteria_pass(node):\n        node.state = COMPLETED\n        propagate_completion_to_parent(node) # ← NEW: parent checks if all children done\n      elif some_criteria_fail(node):\n        node.state = PARTIAL\n      else:\n        node.state = REPLANNING\n        continue\n\n    # ... gates, judge, continuation as before, but scoped to node\n```\n\n### Tree Walker (`tree.next_runnable_node()`)\n\nSelection algorithm:\n1. **Depth-first, priority-ordered**: Walk the tree depth-first; among siblings, highest `priority` first\n2. **Skip terminal nodes**: COMPLETED, PARTIAL, FAILED, CANCELLED\n3. **Skip blocked ancestors**: If a parent is BLOCKED, its children are not runnable\n4. **Respect dependencies**: A node whose parent is not yet COMPLETED is not runnable (unless the parent is PARTIAL and the child is marked `can_run_despite_partial_parent`)\n5. **Return the first runnable leaf-or-internal-node** that is in ANALYZING, DECOMPOSING, EXECUTING, VERIFYING, or REPLANNING state\n\n### Decomposition (`decompose(node)`)\n\nWhen a node enters DECOMPOSING:\n1. The LLM is asked to break the node's objective into 2-7 sub-objectives\n2. Each sub-objective becomes a child `GoalNode` with:\n   - Its own `success_criteria` (inherited from parent's criteria if not specified)\n   - `priority` ≤ parent's priority (ancestor ceiling, same as APEX)\n   - `constraints` inherited from parent\n3. The parent's `child_ids` is populated\n4. The parent transitions to EXECUTING (it's now "executing via children")\n\n### Plan-Per-Node (`get_or_compile_plan(node)`)\n\n1. If `node.plan_id` is set and the plan is still valid (node hasn't entered REPLANNING), return the cached plan\n2. Otherwise, call `CognitiveCompiler.compile(goal=node.objective, ...)` to produce an `ExecutionPlanIR`\n3. Create a `PlanVersion` in the versioned plan store (`alpha.goals`) linked to this node\n4. Store `node.plan_id` and increment `node.plan_version`\n5. Return the plan for execution\n\n### Execution (`execute_plan(node, plan)`)\n\n1. For each `ExecutionWave` in the plan:\n   - Create a `TaskAttempt` in the versioned plan store\n   - Dispatch via `AutonomousDispatchBridge.dispatch()` (or a lighter executor for simple nodes)\n   - Record the result as `GoalEvidence` on the node\n   - Transition the attempt (`pending → running → succeeded/failed`)\n2. If all waves succeed, the node moves to VERIFYING\n3. If a wave fails, the node moves to RECOVERING (then back to EXECUTING or to REPLANNING)\n\n### Propagation (`propagate_completion_to_parent(node)`)\n\nWhen a node completes:\n1. Check its parent\n2. If all of the parent's children are COMPLETED (or PARTIAL), the parent's `success_criteria` are evaluated:\n   - If the parent's criteria are all met → parent moves to COMPLETED\n   - If some are met → parent moves to PARTIAL\n   - If none are met → parent moves to FAILED\n3. Recurse up the tree\n\n---\n\n## Integration with Existing Systems\n\n### 1. Versioned Plan Store (`alpha.goals`)\n\n**Add to `GoalContract`:**\n- `parent_contract_id: str = ""` — links a child contract to its parent\n- `node_id: str = ""` — links the contract to a `GoalNode` in the tree\n\n**Add to `PlanVersion`:**\n- `node_id: str = ""` — links the plan to a specific node\n- `wave_index: int = -1` — which execution wave this plan version corresponds to\n\n**New method on `GoalStore`:**\n- `create_child_contract(parent_contract_id, objective, *, owner_id)` — creates a contract with `parent_contract_id` set, enforcing the same owner and ancestor priority ceiling\n\n**The store already has:** atomic writes, owner scoping, attempt tracking, approval state machine. These are reused as-is.\n\n### 2. APEX Goal Store (`apex/goals.py`)\n\nThe `ApexGoal` model and `ApexGoalStore` are the closest existing system to the design proposed here. Two options:\n\n**Option A (preferred): Merge into the new GoalNode tree**\n- Port `ApexGoal`'s evidence model, `create_child`, `tree()`, `ancestors()`, and `request_completion` into the new `GoalNode` / `GoalTreeStore`\n- Deprecate `ApexGoalStore` as a separate system; the APEX commands layer (`apex/commands.py`) is rewritten to use the new tree\n- This eliminates the "three goal-ish stores" problem the APEX module's own docstring complains about\n\n**Option B: Keep APEX as the read-model, GoalTree as the write-model**\n- `ApexGoalStore` becomes a read-optimized projection of the goal tree\n- More complex; only choose if APEX commands need to stay independent\n\n### 3. Planning Module (`planning/`)\n\n**Add to `CognitiveCompiler`:**\n- `compile_for_node(node: GoalNode, ...)` — compiles a plan for a specific node, storing the `node_id` in the `ExecutionPlanIR`\n\n**Add to `ExecutionPlanIR`:**\n- `node_id: str = ""` — which goal node this plan was compiled for\n- `parent_plan_id: str = ""` — for replanning chains\n\n**The `AutonomousDispatchBridge` is already well-designed** — it dispatches to real subsystems and reports honest results. It needs no changes; it just needs to be called *per node* rather than per flat goal.\n\n### 4. Continuous Goal Runner (`harness/continuous/`)\n\nThe `ContinuousGoalRunner` and its `GoalStore` are the oldest system. Two options:\n\n**Option A (preferred): Migrate to the goal tree**\n- `Goal.milestones` becomes a `GoalNode` tree (or a flat projection of one)\n- `ContinuousGoalRunner.step()` uses `tree.next_runnable_node()` instead of `get_next_runnable_milestone()`\n- The milestone dependency graph becomes the goal tree's parent-child relationships\n\n**Option B: Leave as-is, bridge at the command layer**\n- The continuous runner keeps its flat milestone model\n- A bridge translates between the goal tree and milestones\n- Choose this if the continuous runner is stable and used by other consumers\n\n---\n\n## Migration Path\n\n### Phase 1: Introduce GoalNode (non-breaking)\n1. Add `GoalNode` and `GoalTreeStore` as new types in `mission/goalloop/`\n2. Add `nodes: dict[str, GoalNode]` to `GoalState` (alongside existing `subgoals: list[str]`)\n3. The run loop checks `nodes` first; if empty, falls back to the flat `subgoals` path\n4. No changes to existing callers\n\n### Phase 2: Wire the tree walk into the run loop\n1. Implement `tree.next_runnable_node()` and the tree-walking loop in `GoalLoopEngine`\n2. Implement `decompose(node)` using the existing LLM deliberation seam\n3. Implement `get_or_compile_plan(node)` using `CognitiveCompiler`\n4. Implement `execute_plan(node, plan)` using `AutonomousDispatchBridge`\n5. Implement `propagate_completion_to_parent(node)`\n\n### Phase 3: Link to versioned plan store\n1. Add `parent_contract_id` and `node_id` to `GoalContract`\n2. Add `node_id` and `wave_index` to `PlanVersion`\n3. Add `create_child_contract` to `GoalStore`\n4. Wire `get_or_compile_plan` to create `PlanVersion` records\n5. Wire `execute_plan` to create `TaskAttempt` records\n\n### Phase 4: Merge or bridge APEX\n1. Port `ApexGoal`'s evidence and completion-gate logic into `GoalNode`\n2. Rewrite `apex/commands.py` goal operations to use the new tree\n3. Deprecate `ApexGoalStore` as a separate persistence system\n\n### Phase 5: Migrate continuous runner (optional)\n1. Replace `Goal.milestones` with a `GoalNode` tree projection\n2. Rewrite `ContinuousGoalRunner.step()` to walk the tree\n\n---\n\n## Key Design Decisions\n\n### 1. Why a tree, not a flat list with dependencies?\n\nThe existing `Milestone.dependencies` and `PlanVersion.content` (which can hold a DAG) already express dependencies. But a tree gives:\n- **Inheritance**: children inherit constraints and priority ceiling from ancestors\n- **Independent lifecycle**: each node has its own state, evidence, and completion criteria\n- **Natural decomposition**: the LLM breaks a node into children; the children are first-class\n- **Propagation**: completion flows up the tree automatically\n\n### 2. Why reuse `alpha.goals` (versioned plan store) rather than build new persistence?\n\nThe `GoalStore` already has:\n- Atomic writes with `fsync` and `os.replace`\n- Owner scoping with SHA-256 filenames\n- Approval state machine (draft → approved → superseded)\n- Attempt tracking with legal transitions\n- Corruption detection that fails closed\n\nBuilding a fourth persistence system would be wasteful. The right move is to extend `GoalContract` with `parent_contract_id` and `node_id`, and add `create_child_contract`.\n\n### 3. Why not just use APEX's `ApexGoalStore`?\n\nAPEX's goal store is the closest to what's needed, but:\n- It's a separate persistence system with its own file format\n- It's not wired into the run loop\n- It has 15 states (more than needed for the run loop's purposes)\n- The APEX module's own docstring acknowledges it's "adapted, not extended" from the other stores\n\nThe right move is to port APEX's best ideas (evidence model, completion gate, `create_child`, `tree()`) into the new unified `GoalNode` tree, then make APEX commands a read-model over that tree.\n\n### 4. How does this relate to the planning module?\n\nThe planning module compiles a goal into a plan (task DAG, execution waves, proof obligations). The goal tree tells the planning module *which node* to compile for. The plan's `ExecutionWave`s become `TaskAttempt`s in the versioned plan store. The plan's `proof_obligations` become the node's `success_criteria`.\n\nThis closes the loop: **goal tree → plan → execution → evidence → completion → propagation**.\n\n---\n\n## Risks and Mitigations\n\n| Risk | Mitigation |\n|---|---|\n| **Tree walk infinite loop** (DECOMPOSING → EXECUTING → DECOMPOSING) | Bound decomposition depth (max 4 levels); a node that has been DECOMPOSING twice without producing children is forced to EXECUTE with a trivial plan |\n| **LLM produces too many children** | Cap at 7 children per node; merge or reject excess |\n| **Evidence explosion** (every node has an append-only evidence list) | Prune evidence older than the node's `plan_version` change; keep only the latest measurement per criterion (the `latest_evidence()` pattern) |\n| **Backward compatibility** (existing `subgoals: list[str]` callers) | Phase 1 adds `nodes` alongside `subgoals`; the run loop checks `nodes` first and falls back |\n| **APEX commands break** | Phase 4 rewrites APEX commands to use the new tree; existing APEX goal IDs are migrated to `GoalNode.node_id` values |\n| **Performance** (tree walk on every turn) | Cache the "next runnable node" and invalidate only on state transitions; the tree is typically < 50 nodes |\n\n---\n\n## Summary\n\nThe design introduces a **`GoalNode` tree** as the single source of truth for hierarchical goal decomposition in Alpha. It:\n\n1. **Replaces** the flat `subgoals: list[str]` in `GoalState` with a tree of nodes, each having its own objective, success criteria, evidence, and state\n2. **Wires into the run loop** via a tree walker that selects the next runnable node, decomposes it into children, compiles a plan for it, executes the plan, records evidence, and propagates completion up the tree\n3. **Reuses** the versioned plan store (`alpha.goals`) for contract/plan/attempt persistence, extended with `parent_contract_id` and `node_id` links\n4. **Reuses** the planning module (`CognitiveCompiler` → `ExecutionPlanIR` → `AutonomousDispatchBridge`) for plan compilation and execution, linked to specific nodes\n5. **Ports** APEX's evidence model and completion gate into the new tree, then makes APEX commands a read-model over it\n6. **Migrates** in 5 phases, each non-breaking, with backward compatibility at every step\n
