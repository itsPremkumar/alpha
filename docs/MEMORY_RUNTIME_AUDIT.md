# Memory runtime audit

This audit records the current implementation and reachable runtime paths in Alpha. “Implemented” means code and focused tests exist; “wired” means a normal runtime path reaches that code. A successful unit test or completed agent run alone is not runtime proof. The baseline is a source audit on 2026-10-16; no persisted memory write/recall scenario has yet been run against the live Gateway in this task.

| L1 history-preserving revision (`memory.l1.history_kept`, Hy-Memory 2.0 contract; default off) | When dedup issues `update`/`merge`, the replaced value is kept as a bounded, redacted `MemoryHistoryEntry` chain on the surviving record (count-capped `MAX_HISTORY_ENTRIES`, char-capped per entry, oldest dropped), merged records inherit targets' chains de-duplicated by `(record_id, content)`, `L1RecordStore.put_records()` extends its redaction boundary to history entries, and — only when the gate is on — the recall seam renders a bounded `(prior: …)` tail through `recall_safety.contain_recalled_text`. `RunReport.history_entries` counts entries written this run. History never changes a decision and never rides the dedup candidate prompt. | `backend/tests/test_l1_history.py` (gate default, update/merge/chain/cap, redaction-boundary, recall-tail on/off), `backend/tests/test_l1_persisted_records.py` (report-contract key), `backend/tests/test_memory_evaluation.py` (`alpha-update-003` history-retention + `alpha-extraction-003` assistant-said families; the `alpha-update-003` real-path test models a provider whose history rides inside the current record). No live write→recall run has exercised the gate here; the store remains single-process JSON, not cross-process exactly-once. |
| L1 adoption slices #1–#4 (Hy-Memory/StateMem/STALE/Zep/Mem0 contracts; default off) | Four bounded, independently gated read/marking upgrades. **#1 staleness propagation** (`memory.l1.staleness_propagation`): the dedup seam collects only store-confirmed superseded ids (`apply_decisions(..., superseded_ids=...)`), and the pipeline walks the entity mention lineage (`alpha/memory/entities/`) to mark dependents into an id-only journal `users/{u}/l1/staleness/YYYY-MM-DD.jsonl` (≤32 dependents, `truncated` flag, content and record text never written; `RunReport.stale_dependents` is additive). **#2 conflict expansion** (`memory.l1.conflict_expansion`): dedup recall widens by up to 5 lower-ranked candidates passing a deterministic same-subject/different-value prefilter so implicit invalidations below the `dedup_top_k` cut reach the adjudicator. **#3 as-of recall**: `memory_search(as_of=...)` parses ISO-8601/unix cutoffs (refusing garbage before any search, and refusing outright while `memory.fusion.enabled` is off), and the fused controller applies one central filter — candidates dated after the cutoff (episode `event_time`, fact `createdAt`→`valid_from`) are dropped, undated ones kept; fully-filtered stages report `empty` with the cutoff in the reason. **#4 signal boost** (`memory.l1.signal_boost`): case-sensitive identifier tokens (0.15) and a bounded 14-day recency term (0.10) reorder recall inside the base-score top-k window only. The normal host memory master gate defaults to enabled, but L1 has its own gate. Additive types and cross-cutting features require both `memory.enabled` and their package gate; these package gates default off. L1's gate is also off by default. Disabling an additive subsystem is intended to be a no-op. Owner identity is enforced by runtime identity resolution and per-user stores. `CaptureJob` has user, agent, thread and mode context but no project identifier; the current additive capture seam only accepts `user_id` and writes user scope. Project-specific capture is therefore not implemented and must not be inferred from project UI/shared memory.

## Recommended first vertical slice (P0)

Implemented in this change: the pipeline wires entity/narrative capture after retention and persona refresh, re-reads each confirmed record by ID under the same L1 owner/agent scope, and hands only records still present to the default-off surfaces. When `memory.policy.enabled` is true, `AdmissionEngine.from_config()` runs before the downstream writes and a rejection prevents those writes. `RunReport.capture_outcome` includes per-surface status/count/detail in the returned report and provenance log. Surface errors are logged and do not invalidate the durable L1 write. `CaptureJob` has no project ID and the entity/narrative stores are owner scoped, so this slice does not provide project-level memory isolation.

Also implemented: `GET /api/memory/status` includes an `l1_capture` read-only projection for the authenticated owner. The reader scans no more than seven days, 128 KiB and 500 lines per day; the response drops content, record IDs and free-form detail. Disabled, no-recent-run, old-format, degraded and unreadable states remain distinct. The existing Memory overview displays this projection; a failed API read shows an unavailable state. This is local provenance metadata, not evidence of recall success or multi-process exactly-once behavior.
